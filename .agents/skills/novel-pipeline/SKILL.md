# 小说全自动写作流水线 v2

## 合规引擎（v2 新增）

> [!important] 合规是写作流水线的硬约束，审计代理会逐章执行合规检查。

### 1. 公司/平台名虚构化映射

禁止在小说中直接使用现实公司名或产品名。一律替换为虚构名：

| 现实名称 | 虚构名称 |
|----------|----------|
| 字节跳动 | 炬火科技 |
| 阿里 | 金衡 |
| 美团 | 快达 |
| 百度 | 千寻 |
| 抖音 | 轻舟 |
| 微博 | 微言 |
| 知乎 | 知否 |
| 腾讯 | 星洲 |
| 拼多多 | 集惠 |
| 京东 | 东来 |
| 快手 | 闪拍 |
| 小红书 | 红笺 |
| B站 | 次元站 |

**规则**：若章节需要提及上述列表之外的真实公司，写手必须自行虚构映射，并在章节末尾的「虚构映射附注」中登记。

### 2. 暗示而非明示

通过虚构映射间接反映行业普遍现象，不直接指控具体公司或个人。

**策略示例**：
- "天衡科技利用推荐算法进行情绪化内容分发" —— 暗示行业问题，但不指明具体公司
- 虚构公司"天衡科技"的行为可暗示行业普遍问题
- 场景和事件应为类型化描写，不指向可定位的具体事件

### 3. 免责声明模板

每章末尾必须附加：

```
> [!notice] 免责声明
> 本作品为虚构小说。书中出现的所有公司名称、产品名称、人物、事件均为虚构。
> 如有与现实公司名、产品名、人名相似之处，纯属巧合。本作品旨在探讨技术伦理
> 与人性议题，不构成对任何现实实体或个人的影射或指控。
```

全书开头（第一章之前或序章）必须附加扩展版免责声明：

```
> [!notice] 全书免责声明
> 本作品为虚构小说。书中出现的所有公司名称（如炬火科技、天衡科技、金衡、快达、
> 千寻、轻舟等）、产品名称、人物、地点、事件均为虚构。任何与现实公司、产品、
> 人物、地点的相似之处纯属巧合。本书探讨的技术伦理、社会议题属于普遍性讨论，
> 不构成对任何具体现实实体或个人的影射、指责或指控。作者保留对虚构世界观的最
> 终解释权。
```

### 4. 出版前审计清单

审计代理每章必须校验以下清单（零容忍红线）：

- [ ] 真实公司名为 0（含中英文、缩写、曾用名）
- [ ] 真实平台/产品名为 0
- [ ] 无具体可定位地址（城市/区域可保留，但无完整门牌号或地标）
- [ ] 无真实人物姓名（含公众人物、历史人物）
- [ ] 有虚构声明（免责声明块）
- [ ] 映射附注表中无遗漏

**审核输出**：审计代理在 audit 文件中添加「合规审计」小节，逐项标注通过/阻塞。

### 5. 破折号规范

| 规则 | 限制 |
|------|------|
| 每段最多破折号数 | ≤3 |
| "不是X——是Y"句式每章上限 | ≤2 |
| 破折号替代方案 | 优先使用逗号、分号重构长句 |

审计代理额外检查破折号违规，超标即阻塞。

## 核心概念

本 skill 将小说写作拆解为四种原子任务，由10个子代理并行调度（固化代理待创建：`@novel-writer`、`@novel-auditor`、`@novel-fixer`）：

| 角色 | 代理类型 | 每次调度数 | 功能 |
|------|---------|-----------|------|
| 写手 | general（待固化） | 4-5 | 基于大纲写新章节（含合规映射） |
| 审计 | general（待固化） | 4-5 | 交叉审核（支持者+批评者合报 + 合规审计） |
| 修复 | general（待固化） | 1-2 | 根据审计阻塞清单精确修复（含合规修复） |
| 同步 | general | 1 | 更新大纲/索引/版本号/映射附注表 |

## 启动指令

用户说"继续"或其他触发词后，执行以下流程：

### Step 1: 状态扫描
读取 `outline_v1.md`，确定：
- 已完成章节数
- 最新章节结尾内容
- 下一批待写章节的大纲预设
- 是否有未修复的审计阻塞（含合规阻塞）

### Step 2: 分配10个子代理
优先分配规则：
- 若有已审计但未修复的阻塞（含合规阻塞） → 分配1-2个修复代理（优先于写手）
- 若有已写但未审计的章节 → 分配审计代理
- 剩余槽位全部给写手（按大纲顺序逐章撰写）
- 最后1个槽位给同步代理

### Step 3: 并行发射
一次 `task` 调用中发射全部10个子代理，输出路径统一为：
```
swarm_reports/novels/<书名>/chapters/chapterNN.md
swarm_reports/novels/<书名>/audit/chapterNN_audit_vN.md
swarm_reports/novels/<书名>/compliance/mapping_vN.md
```

### Step 4: 结果核验
全部子代理返回后：
- 检查是否有新阻塞项（含合规阻塞）
- 合规红线阻塞 → 阻塞最高优先级，必须立即修复
- 若阻塞 > 0 → 下一轮优先修复
- 若阻塞 = 0 → 持续扩展新章节
- 每完成10章 → 打 git tag

## 注册代理

本 skill 依赖以下固化精锐代理（位于 `.opencode/agent/`，均待创建）：

| 代理 | 文件 | 调用方式 |
|------|------|---------|
| 写手 | `novel-writer.md`（待创建） | `subagent_type: general`（注入写手规则 + 合规映射表 + 免责声明模板） |
| 审计 | `novel-auditor.md`（待创建） | `subagent_type: general`（注入审计规则 + 合规审计清单） |
| 修复 | `novel-fixer.md`（待创建） | `subagent_type: general`（注入修复规则 + 合规红线修复） |

**v2 子代理上下文注入**：每次调度子代理时，必须在 prompt 中注入：
1. 合规映射表（本章节可能涉及的公司/平台）
2. 免责声明模板
3. 出版前审计清单
4. 破折号规范
