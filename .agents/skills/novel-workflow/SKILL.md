## 触发场景

- 想开始写一部新小说，先要调研市场
- 设计小说的世界观、书名或封面方向
- 逐章生成小说正文并归档
- 审核已写好的小说章节

## 核心原则：先调研再做

**任何小说创作任务开始前，必须先调研市场和现状，再行动。**

**调研需覆盖两个维度：目标小说平台 + 社交媒体热点。**

| 任务类型 | 平台侧调研 | 社交热点侧调研 |
|----------|-----------|---------------|
| 创作新小说 | 目标平台热门题材、用户画像、变现模式 | 抖音/微博/小红书/B站等平台的热搜、热议话题、情感风向 |
| 设定书名/封面 | 同类热门书名关键词、评论反馈 | 社交平台高频情绪词、流行梗、传播性标题风格 |
| 世界观设计 | 同类型热门小说世界观套路 | 当下社会情绪、圈层文化热点、泛娱乐趋势 |

### 调研流程

> [!tip] 使用 defuddle 提取网页正文
> 加载 `defuddle` skill，用 `defuddle parse <url> --md` 命令提取小说平台和社交媒体的正文内容。
> 相比 WebFetch，defuddle 去除导航栏/广告/杂讯，节省 60%+ token。

1. **web 提取**：加载 `defuddle` skill，对目标 URL 执行 `defuddle parse <url> --md`
2. **双线并行**：加载 `swarm-orchestrate` skill，派生子代理同时调研小说平台和社交热点
3. **交叉分析**：将平台数据与社交热点对照，找出题材 × 情绪的交汇点
4. 基于调研结果制定方案
5. 执行并验证

---

## 创作能力要求

小说创作是个系统工程，需协调多种能力：

- **调研**：加载 `swarm-orchestrate` skill，派生子代理并行调研市场
- **世界观**：加载 `swarm-orchestrate` skill，派生子代理设计世界规则、角色网络
- **正文**：派生子代理逐章创作
- **审核**：加载 `swarm-orchestrate` skill，派生子代理交叉审核
- **自进化**：完成后加载 `self-evolution` skill，沉淀经验、固化精锐代理

## 产出归档规范

### 目录结构

```
swarm_reports/
├── index.md                # 总索引（按 [[knowledge-management]] 规范维护）
├── novels/
│   ├── 小说名/
│   │   ├── world/          # 世界观设计
│   │   │   └── [书名]
_world_v1.md
│   │   ├── chapters/       # 正文章节
│   │   │   ├── chapter01.md
│   │   │   └── chapter02.md
│   │   ├── audit/          # 审核报告
│   │   │   └── [书名]
_audit_v1.md
│   │   └── index.md        # 本书索引
│   └── [其他小说]/
└── 2026-05-01/             # 按日期组织的报告
```

### 命名规范

- 世界观：`[书名]
_world_v[版本].md`
- 正文：`chapter[序号].md`
- 审核：`[书名]
_audit_v[版本].md`

### 子代理输出命令示例

创作小说正文时，强制指定正确输出路径：
```
[输出到: swarm_reports/novels/心晴咖啡馆/chapters/chapter01.md]
```
