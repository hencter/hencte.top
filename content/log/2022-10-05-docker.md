> **历史说明（2026 年 11 月修订）**：2022 年这篇笔记只有一条 `mysql:5.7` 的启动命令，并在命令行中使用了 `root` 作为 root 密码。MySQL 5.7 已结束常规维护，不建议把这条旧命令直接用于新的开发环境，更不能照搬到公网服务器。下面保留当年的用途，但换成更稳妥的本地开发示例。

## 1. 准备 MySQL 密码

在工作目录创建本地环境变量文件 `.env.mysql`：

```dotenv
MYSQL_ROOT_PASSWORD=请替换为你自己的强密码
```

不要将这个文件提交到 Git；如果是共享或生产环境，应使用合适的密钥管理方式，而不是把真实密码写进仓库。

## 2. 创建数据卷并启动容器

这里使用 MySQL 8.4 LTS，端口只绑定在本机回环地址，数据保存在 Docker 命名卷中：

```bash
docker volume create mysql-dev-data

docker run --name mysql-dev -p 127.0.0.1:3306:3306 --env-file .env.mysql -v mysql-dev-data:/var/lib/mysql -d mysql:8.4
```

这样本机可以连接 `127.0.0.1:3306`，但不会因为 `-p 3306:3306` 而默认监听所有主机网卡。若本机 3306 已被占用，请调整映射到的宿主机端口。

## 3. 验证与连接

```bash
docker ps --filter name=mysql-dev
docker logs mysql-dev
docker exec -it mysql-dev mysql -uroot -p
```

最后一条命令会提示输入密码。首次初始化需要一点时间；如果连接失败，先看容器日志，而不是反复删除重建。

不再需要容器时可以使用 `docker rm -f mysql-dev` 删除容器；**命名卷不会因此自动删除**，已有数据仍可保留。

## 为什么不沿用旧命令？

原文只解决了“怎样让 MySQL 跑起来”，没有处理三个实际问题：旧版本维护状态、明文弱密码、数据库数据在容器删除后的保存。把这些前提写清楚，才是一条值得长期留存的开发笔记。
