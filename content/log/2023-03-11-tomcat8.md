> **历史记录（2026 年 11 月修订）**：本文最初整理于 2023 年，日期是旧笔记迁移时的记录日期，并非故障发生的精确时间。Tomcat 8.5 已于 2024 年 3 月 31 日结束官方支持；新项目应优先选择仍受支持的版本。[版本说明](https://tomcat.apache.org/tomcat-85-eol)

当时为了在 IntelliJ IDEA 中开发和调试 Java Web 项目，我采用了下载 ZIP 压缩包、解压后手动指定 Tomcat 目录的方式。遇到的报错主要有两类，虽然有时一起出现，但原因和处理方式不同。

## 1. Error copying configuration files：先检查目录权限

IDEA 在启动本地 Tomcat 配置时，可能需要复制或写入配置文件。如果源目录不可读，或目标配置目录不可写，就可能出现复制失败。

在 Linux 上先检查实际目录、所有者和权限：

```bash
# 将路径替换成实际的 Tomcat 安装或实例目录
ls -ld /path/to/tomcat/conf
ls -l /path/to/tomcat/conf
```

处理时应先确认 **IDEA 使用的是哪个配置目录**，以及执行 IDEA 的用户是谁：

- 如果是本机开发，优先将 Tomcat 实例的可写配置放在当前用户有权限的位置。
- 如果安装在系统目录，按实际使用者与服务账号调整**必要文件或目录**的属主、属组和权限。
- 不要为了绕过一次复制失败，就对整个 `conf` 目录执行 `chmod 777`。这会让无关用户也获得写入配置的权限，扩大安全风险。

具体授权应以实际部署方式为准，不建议直接复制一条通用的 `chown` 或 `chmod` 命令。

## 2. Address localhost:8080 is already in use：检查端口占用

这是**端口冲突**，不能通过修改配置文件权限解决。先查出哪个进程正在监听 8080：

```bash
sudo ss -ltnp | grep ':8080'
```

如果已经有另一个 Tomcat 实例或其他服务占用该端口，可以停止冲突服务，或者在 IDEA 的运行配置及对应的 Tomcat Connector 设置中改用空闲端口。不要在没有确认进程用途之前直接终止它。

## 3. 复盘

当年的笔记把“复制配置失败”和“端口被占用”混为一个问题，还推荐过给配置文件开放最大权限。现在看来，正确顺序应该是：**先分清报错来源，再定位目录或进程，最后做最小范围的修改。**
