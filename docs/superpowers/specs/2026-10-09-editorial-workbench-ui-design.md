# 亦幸小阁「编辑部 × 产品工作台」UI 改造设计规格

## 目标

把站点从“统一卡片组成的个人博客”升级为一个有编辑气质的个人产品工作室：

- 首页能同时表达个人身份、当前工作和内容入口。
- GitHub 项目像产品展厅，能快速看懂项目是什么、是否活跃、如何访问。
- 博客和文章保持长时间阅读的舒适度。
- 小说拥有独立的沉浸式阅读感。
- 四语、深色模式、静态构建、现有 URL、SEO 和抓取策略继续有效。

## 已确认的设计方向

采用“编辑部杂志风 × 产品工作台”。视觉基底继续使用米白宣纸、青墨和朱红，但通过更清楚的层级、栏目色彩和版式节奏，区分项目、文章和小说三类内容。

这套方向来自站点实际内容：作者近期同时维护 Hugo / Tailwind 工具链、Nova、通天路、Workers Ledger 等产品与实验，并持续写技术文章、维护 Obsidian 知识系统和原创小说。页面需要承载这些不同内容，而不是把所有内容压成同一种卡片。

## 设计原则

1. **内容先于装饰**：颜色、插图和卡片只用于建立层级，不承担正文信息。
2. **精选与列表分级**：重点项目和最新内容拥有更大的视觉面积，其余内容保持可扫描。
3. **每一屏都有主任务**：首页引导进入项目或文章，项目页帮助判断项目，文章页帮助阅读，书架帮助继续阅读。
4. **静态优先**：不引入客户端框架、运行时 API 或必须联网才能显示的 UI 数据。
5. **多语和深色同构**：组件结构、间距和语义 token 共享，文案和色彩在各语言与主题下都能独立校正。

## 页面设计

### 全局壳层

- Header 保留站点名称、主导航、语言切换和主题切换，但提高当前项识别度。
- 桌面端导航保持轻量；移动端菜单扩大点击区域，菜单打开后不挤压正文。
- 页面主容器采用内容类型对应的最大宽度：品牌页和项目页偏宽，文章页偏窄，小说阅读页保持独立阅读宽度。
- Footer 从简单版权区升级为站点入口和内容轨道说明，但控制在较短高度内。

### 首页

- Hero 采用“身份 / 当前动作 / 入口”的三层结构，标题、当前项目或近期动作、主要入口分别形成清晰层级。
- 项目区使用精选项目卡片，第一张或主项目可拥有更大面积，其余项目采用统一网格。
- “最新写作”使用时间线式列表，显示 section、日期和标题，避免和项目卡片混在一起。
- 小说区保留封面卡片，但用独立背景或分隔方式表明它是另一条内容轨道。
- 可加入一块轻量“最近在做什么”信息条，数据只来自已提交的站点内容或生成的项目数据，不引入实时 API。

### 项目页

- 精选项目卡片包含封面、项目状态、描述、主入口和 GitHub 元数据。
- GitHub 元数据使用紧凑信息条显示主要语言、Star、最近推送日期、许可证和仓库入口。
- 有演示站和仓库的项目分成两个明确动作；只有仓库的项目不制造假的产品入口。
- 没有图片的项目使用统一的内容型占位视觉，不能因为缺少封面改变卡片高度。
- “更多项目”降低字号和视觉权重，强调快速浏览，不与精选项目争夺首屏注意力。

### 博客与 section

- 博客首页作为杂志目录，先展示栏目入口，再展示最新文章。
- 日志、技术、古文和 Obsidian section 使用各自 banner、简介和文章列表。
- 文章卡片显示日期、栏目、摘要和阅读入口；摘要高度统一，避免网格跳动。
- 技术子栏目保持导航关系，但不再让每个子栏目产生完全不同的卡片外观。

### 文章页

- 首屏顺序为栏目识别、标题、日期 / 阅读时间、文章首图或栏目 banner、目录和正文。
- 正文使用窄阅读列；桌面端目录固定在右侧，移动端折叠到正文上方。
- 相关文章、上下篇和标签放在正文结束处，形成下一步阅读路径。
- 代码、表格、引用和 callout 使用同一套纸面组件 token，避免每类内容独立换肤。

### 书架与章节

- 书架首页突出作品封面、简介和继续阅读入口。
- 单本小说落地页用封面、作品信息和章节目录建立“书”的感觉。
- 章节页保留当前的保护策略和 canvas 阅读能力，优化顶部导航、章节索引和底部翻页的视觉关系。
- 小说区可以使用更深的背景或更明显的纸张纹理，但不改变全局导航和可访问性。

## 视觉系统

### Token

继续使用语义 token，并补充以下角色：

- `surface` / `surface-soft` / `surface-raised`：页面、纸面、浮起卡片。
- `ink` / `ink-soft` / `ink-muted` / `ink-faint`：标题、正文、说明、元信息。
- `accent`：全局朱红动作色。
- `section-log`、`section-tech`、`section-ancient`、`section-obsidian`：栏目识别色，必须满足正文文字对比度。
- `line` / `line-strong`：发丝边和交互边。

### 版式

- 标题使用更强的编辑部层级，正文继续使用适合中文长文的衬线或现有 LXGW 文楷组合。
- 统一 section 标题、页面标题、卡片标题和正文标题之间的比例。
- 用空间区分内容组，减少大面积重复边框。
- 所有重要交互保持可见 focus 状态，点击区域在移动端不小于舒适触控尺寸。

## 技术边界

- 主要修改 `themes/kiss/assets/css/main.css`、页面模板和 partial。
- 必要时添加少量数据字段，但不把 GitHub 动态字段复制到文案 TOML；继续由 `data/projects/live.json` 提供客观数据。
- 不修改已冻结 URL，不改变语言配对路径，不改变 draft、Cite、Protect 规则。
- 不使用客户端组件实现布局、筛选或导航；能用 Hugo 模板和 CSS 完成的功能不增加 JavaScript。
- 图片继续通过统一的 `img.html` 解析，避免各模板自行处理资源。

## 分阶段实施

1. 重构全局 token、排版、header、footer、按钮、卡片和响应式容器。
2. 改造首页与项目页，建立精选项目和 GitHub 数据的视觉层级。
3. 改造博客首页、section 列表和文章页，统一阅读路径。
4. 优化书架、小说落地页和章节导航，完成内容轨道区分。
5. 做明暗主题、四语、390px 移动端和桌面端回归。

## 验收标准

- `pnpm build` 无 warning、无重复路径、四语页面全部生成。
- `pnpm check` 的 live URL、alias、发布页面、图片和语言切换全部通过。
- 首页、项目页、博客页、section、文章页、书架和章节页在 390px 与桌面宽度下无横向溢出。
- 明色和暗色主题的正文、元信息、链接、按钮和 focus 状态满足可读性要求。
- GitHub 项目卡片在 live 数据缺失、项目无图片、只有仓库或同时有演示站的情况下都能稳定渲染。
- 不引入新的运行时依赖，不改变既有 URL 和抓取策略。
